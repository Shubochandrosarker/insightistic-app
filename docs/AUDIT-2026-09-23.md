# Insightistic Current-State Audit — 2026-09-23

Source of truth: repository code at `main @ 5d8e877` (post phases 1–15 + P0 of the
2026-09 roadmap). This audit responds to the 2026-09-23 advisor review: **connection
architecture is the first engineering milestone** — a customer can see working
analytics inside WordPress while the SaaS presents Google as "not connected".

Legend: COMPLETE = exists and healthy · PARTIAL = exists but wrong/incomplete ·
MISSING = does not exist.

## 1. Platform architecture

| Area | State | Notes |
|---|---|---|
| Org-level provider accounts (`provider_accounts`) | **MISSING** | Google tokens live per-site in `data_source_credentials` (`unique(site_id, source)`). Connecting 5 sites = 5 Google consents for the same Google account. |
| Platform-neutral Site model | **MISSING** | `sites.platform` defaults `'woocommerce'`; `SiteController::store` hardcodes it. No `canonical_url`, `detected_platform`, `platform_override`, `country`, `language`, `status` columns. |
| Capability model (`has_search_data`, …) | **MISSING** | Only per-endpoint `has_data` flags. No scattered `platform ===` checks either (good). |
| URL-only site creation | **PARTIAL** | `POST /sites` works (no license needed) but is labeled "legacy connector", defaults woocommerce, queues nothing (no crawler/uptime/PageSpeed), no duplicate detection. |
| Domain normalization + dedupe | **PARTIAL** | `LicenseService::normalizeSiteUrl` used on plugin activation only; URL create path has none. |
| GSC property → site import | **MISSING** | `/sites/{site}/integrations/gsc/resources` lists properties, `select` binds ONE property to an EXISTING site. No multi-select import, no site creation. |
| Connection-method tracking (`connection_method`) | **MISSING** | `data_source_connections` has no method column; `IntegrationsController` derives `auth_type` at read time; plugin v2 pushes stamp the same `gsc`/`ga4` connection rows as OAuth. |
| Plugin-vs-direct UI state | **PARTIAL** | Two sections exist on Integrations page, but GSC/GA4 always render as direct cards; when the plugin feeds them, UI shows "Connected" with no credential and no "Connect directly" affordance — the advisor's screenshot scenario. |
| Bing | **PARTIAL** | API-key paste only; UI copy claims "Bing has no OAuth" (false). Works functionally. |
| Cloudflare | **COMPLETE** (token-based) | Scoped API token + zone picker; encrypted on `sites`. OAuth absent but token flow is acceptable primary per spec §11 with OAuth preferred. |
| Overview "Site Health" | **PARTIAL** | Overview tile renders connector `connection_status`, not health. Real `CrawlHealthScore` service exists but is surfaced only on Audit page + Agency portfolio. |

## 3. Billing (Paddle)

Webhook HMAC + replay window, `billing_events` idempotency, queued processing,
LTD one-time → `entitlement_grants`, credit packs, daily reconciler command,
cancellation/pause/resume projection, server-side purchase projection: **COMPLETE**.
Gaps: failed-payment email missing on Paddle path; **credit metering has zero
callers** (`CreditLedger::consume` unwired) while terms claim "credits power AI
visibility runs"; unknown statuses keep access (reconciler compensates).

## 4. Marketing attribution & events

**MISSING entirely.** No UTM/gclid/fbclid capture, no first/last-touch storage, no
`signup_completed`/`site_added`/`purchase_completed` event taxonomy (telemetry
tables are ops metrics only). Purchase IS recorded server-side from verified
webhook (good foundation).

## 5. Public claims vs reality

- No "unlimited"-style claims (good).
- App-level public pages: pricing/terms/privacy/login/register exist; marketing
  homepage lives on the WordPress site (insightistic.com) by design.
